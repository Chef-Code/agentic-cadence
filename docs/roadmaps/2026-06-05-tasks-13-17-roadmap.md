# Tasks 13-17 Roadmap

> **For agentic workers:** Use `docs/roadmaps/2026-06-05-tasks-13-17-roadmap.md` as the public planning artifact after Tasks 8-12. Implement each task on its own branch and update the living docs with evidence before merge.

**Goal:** Move Agentic Cadence from read-only local work ownership evidence toward ownership-bound execution and role-aware readiness, without adding hidden real-executor invocation, autonomous GitHub writes, merge, release, or package-publication authority.

**Architecture:** Cadence remains the governor. It may write local ownership and audit evidence when an explicit command is approved, but ownership records remain local evidence, not distributed locks or GitHub assignment authority.

**Tech Stack:** Python 3.11+, stdlib CLI, local JSON packets, Git, optional `gh` only for already-approved explicit evidence capture paths, `unittest`, GitHub Actions.

## Phase Ladder

Tasks 13-17 continue the staged path:

1. **Phase 4: Multiple workers, local first** - create and close local ownership records before any remote agent pool exists.
2. **Phase 2: Governed execution hardening** - make execution-start and resume-continuation respect local ownership evidence.
3. **Phase 5: Agent-team orchestration preparation** - add role and review-separation readiness packets before role assignment or paid review automation.
4. **Phase 2/5 bridge: Real executor readiness** - define a preflight packet for future real executor invocation while still reporting `executor_started: false`.

## Task 13: Add Local Work Ownership Claim And Closeout

**Status:** Planned.

**Phase:** Phase 4 preparation, local-only write side.

**Why now:** Task 12 can read and validate ownership records, but no public command can create, close, or fail those records under governance. Before execution-start or resume-continuation can depend on ownership, Cadence needs an explicit local write path with stable blockers and audit evidence.

**Likely files:**
- Modify: `codex_cadence/ownership.py`
- Modify: `codex_cadence/cli.py`
- Modify: `codex_cadence/store.py`
- Modify: `codex_cadence/policy_audit.py`
- Test: `tests/test_cadence.py`
- Docs: `README.md`, `docs/protocol.md`, `docs/autonomous-loop-readiness.md`, `docs/implementation-slices.md`, `docs/progress-log.md`, `docs/decision-log.md`

**Implementation outline:**
- Add explicit local commands to create, close, and fail `work-ownership.v1` records under `<root>/work-ownership/{active,closed,failed}`.
- Require task id, candidate id, role label, claimer, repo, branch, and current repo anchors for active claims.
- Recheck current branch, `HEAD`, dirty-worktree state, duplicate active ownership, stale active ownership, malformed existing records, and registry path safety before writing.
- Emit stable packets such as `work-ownership-claim.v1` and `work-ownership-closeout.v1` with blocker codes and recommended next actions.
- Append compact local audit evidence for accepted ownership mutations.
- Keep records local; do not assign GitHub issues, schedule agents, claim distributed locks, start epochs, invoke executors, create branches, commit, push, merge, release, or publish packages.

**Validation:**
- Valid claim writes exactly one active record with expected task, candidate, role, claimer, repo, branch, and head anchors.
- Duplicate active ownership blocks before writing.
- Dirty worktree, wrong branch, stale head, malformed registry state, stale active ownership, invalid role label, and invalid claimer block with stable codes.
- Closeout moves an active record to `closed` or `failed` with closeout evidence and blocks missing, mismatched, closed, or malformed records.
- Audit replay recognizes ownership mutation records.

## Task 14: Bind Work Ownership To Governed Execution Start

**Status:** Planned.

**Phase:** Phase 2 governed execution hardening.

**Why now:** `start-governed-execution` can start one approved active epoch, but it does not yet prove that the task is locally owned by the claimer or role that is about to hand work to an executor. After Task 13 creates governed local ownership records, execution-start should be able to fail closed on missing, stale, duplicate, or mismatched ownership evidence.

**Likely files:**
- Modify: `codex_cadence/ownership.py`
- Modify: `codex_cadence/epochs.py`
- Modify: `codex_cadence/cli.py`
- Modify: `codex_cadence/policy_audit.py`
- Test: `tests/test_cadence.py`, `tests/test_epochs.py`
- Docs: `README.md`, `docs/protocol.md`, `docs/autonomous-loop-readiness.md`, `docs/implementation-slices.md`, `docs/progress-log.md`, `docs/decision-log.md`

**Implementation outline:**
- Extend `start-governed-execution` to optionally, then deliberately, consume an active local ownership record or ownership status packet.
- Recheck ownership task id, candidate id when present, role label, claimer, repo, branch, `HEAD`, PR, handoff, and freshness against the reviewed task packet and current repo state.
- Block missing, duplicate, stale, closed, failed, malformed, repo-mismatched, branch-mismatched, task-mismatched, and claimer-mismatched ownership with stable codes.
- Bind the started epoch id back to local ownership evidence only after the existing execution-start gates pass.
- Continue to report `executor_started: false` and keep real executor invocation out of scope.

**Validation:**
- Matching active ownership allows an otherwise valid approved execution start.
- Missing or mismatched ownership blocks before epoch mutation.
- Duplicate active ownership blocks before epoch mutation.
- Existing execution-start blockers still win when repo, approval, brake, policy, or active epoch state is invalid.
- Ownership epoch binding happens only after epoch start succeeds and is audit replayable.

## Task 15: Bind Work Ownership To Resume Continuation

**Status:** Planned.

**Phase:** Phase 2 governed execution across sessions.

**Why now:** `resume-continuation` can bind a saved resume verifier packet to a fresh execution-start recommendation, but it does not yet check whether the resumed work is still locally owned by the expected claimer or role. Ownership must be rechecked at the continuation boundary before a fresh session is handed to execution-start.

**Likely files:**
- Modify: `codex_cadence/handoff_loop.py`
- Modify: `codex_cadence/ownership.py`
- Modify: `codex_cadence/cli.py`
- Test: `tests/test_handoff_loop.py`, `tests/test_cadence.py`
- Docs: `README.md`, `docs/protocol.md`, `docs/autonomous-loop-readiness.md`, `docs/implementation-slices.md`, `docs/progress-log.md`, `docs/decision-log.md`

**Implementation outline:**
- Let `resume-continuation` consume local ownership evidence for the resumed handoff, task, branch, and claimer.
- Recheck ownership status after the existing resume verifier, repo, brake, clean-square, policy, active epoch, and freshness checks.
- Recommend `claim_work_ownership`, `refresh_ownership_evidence`, `close_or_fail_active_ownership`, `inspect_resume_blockers`, or `start_governed_execution`.
- Keep the command read-only: no handoff claim, ownership claim, epoch start, executor invocation, branch creation, PR write, merge, release, or publication.

**Validation:**
- Matching active ownership and fresh resume evidence recommends `start_governed_execution`.
- Missing, stale, duplicate, closed, failed, repo-mismatched, handoff-mismatched, task-mismatched, or claimer-mismatched ownership blocks with stable codes.
- Existing resume-continuation blockers remain stable and are not hidden by ownership checks.
- The command reports `read_only: true`, `executor_started: false`, `epoch_started: false`, and no side effects.

**Status:** Planned.

**Phase:** Phase 2/5 bridge, pre-invocation only.

**Why now:** The first hard stop in real unattended operation is still real executor invocation. After ownership and role readiness are bound to execution-start and resume-continuation, Cadence needs one final read-only packet that proves whether a real executor could be invoked later, without invoking it in this slice.

**Likely files:**

**Implementation outline:**
- Add a read-only `executor-invocation-readiness.v1` packet that consumes a reviewed task packet, current active epoch evidence, ownership evidence, command policy, branch policy, expected result path, and optional role-readiness evidence.
- Recheck repo path, branch, `HEAD`, dirty-worktree state, active brake, active epoch id/status, task checksum, ownership binding, result path boundaries, command policy shape, and required checks.
- Emit stable blocker codes and a recommended next action such as `invoke_real_executor`, `refresh_task_evidence`, `fix_ownership`, `close_or_fail_active_epoch`, `inspect_policy_blockers`, or `operator_review`.

**Validation:**
- Fully matching task, epoch, ownership, policy, repo, and role evidence recommends `invoke_real_executor` while still reporting `executor_started: false`.
- Missing active epoch, stale head, dirty worktree, non-`DRIVE` brake, mismatched task checksum, missing ownership, duplicate ownership, invalid result path, malformed policy, and failed role readiness block with stable codes.
- The command is read-only and leaves epoch, ownership, Git, and GitHub state unchanged.

## Recommended Order

1. Task 13 creates and closes local ownership records explicitly.
2. Task 14 makes governed execution start respect active ownership.
3. Task 15 makes resume continuation respect active ownership.
4. Task 16 adds role-policy and review-separation readiness without assigning roles.
5. Task 17 adds real-executor invocation readiness planning without invoking a real executor.

## Boundaries For All Five Tasks

- No hidden real executor invocation.
- No autonomous code modification.
- No dirty-worktree commit path.
- No autonomous branch creation, push, or PR create/update.
- No GitHub issue assignment, review-thread resolution, or comment writes.
- No paid review spending.
- No auto-merge.
- No release or package publication.
- No named host adapter claim.
- No shared remote runtime or distributed lock claim.
- No role assignment or agent-pool scheduling until an explicit later roadmap slice approves it.
